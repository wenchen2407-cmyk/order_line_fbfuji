一、 核心業務定位與系統效益
================================================================================
1. 痛點解決：
   - 出國連線採購結束後，賣家在試算表中標記完各商品的「採購成功」或「缺貨斷貨」，過去需手動逐一打字私訊買家對帳，耗時且容易漏訊。
   - 使用 LINE 官方帳號 (LINE Official Account) 群發推播，每月免費額度僅 200 則，群發結帳通知會瞬間爆額並產生昂貴帳單。
2. 系統效益：
   - 本功能透過 LINE LIFF 官方的 `shareTargetPicker` 技術，直接在賣家個人的 LINE 好友中進行 1 對 1 發送。
   - 【0 則數消耗、終生免費】，完全不計入官方帳號每月推播則數。
   - 買家收到客製化專屬卡片後，一鍵點擊即可直達個人專屬查單頁面 (`my-orders.html`)，完成跨商品合併結帳、選擇 7-11 賣貨便 / 全家好賣+ / 宅配門市並填寫匯款資訊。

================================================================================
二、 試算表資料庫與全自動化運作流程
================================================================================
1. 步驟一【現場採購標記】：
   賣家於 Google 試算表【訂單明細】第 19 欄 (S 欄)「採購/出貨狀態」，將登記訂單下拉標記為：
   - 「採購成功」
   - 「缺貨斷貨」
2. 步驟二【後台自動歸戶彙整】：
   賣家開啟管理後台【📢 顧客結帳通知 (1對1免額度)】分頁，系統調用後端 API：
   - 自動將相同 `LINE_User_ID` 的顧客多筆訂單進行歸組。
   - 統計：採購成功件數、缺貨件數、應付商品總金額。
   - 結合【顧客歸戶】工作表帶出最新真實姓名與聯絡電話。
3. 步驟三【一鍵喚起發送】：
   賣家點擊名單旁的「🚀 發送 1 對 1 卡片」，手機 LINE 自動彈出好友清單，勾選該買家即可發送。
4. 步驟四【買家即時結帳】：
   買家點擊卡片上的「💳 點此開啟清單選擇門市與結帳」，立即開啟 `my-orders.html?uid=...` 進行合併結帳。

================================================================================
三、 待通知顧客判定規則與資料庫篩選邏輯
================================================================================
系統掃描【訂單明細】工作表時，嚴格依據以下條件進行過濾：
1. 未結帳篩選：
   - 結帳編號 (第 22 欄 V 欄) 須為空白。
   - 付款狀態 (第 17 欄 Q 欄) 不為「已完成付款」或「已付款待對帳」。
2. 採購狀態篩選：
   - 名下至少有 1 筆訂單為「採購成功」、「連線登記」或「通知結帳」。
3. 全數缺貨保護：
   - 若該顧客登記的商品全數皆為「缺貨斷貨」，系統標註為「⚠️ 全數斷貨」，阻擋發送結帳卡，改為提供「斷貨慰問通知」。
4. 排序規則：
   - 依顧客「採購成功總金額」由大到小排序，讓賣家優先通知大單、高客單價顧客。

七、 後端 Google Apps Script (Code.gs) API 規格與防呆設計
================================================================================
1. 查詢 API 端點：`GET ?action=getCustomerNotifyList`
   - 自動遍歷【訂單明細】，過濾未結帳且有採購成功的買家，回傳顧客統計與商品清單 JSON。
2. 標記已通知 API：`POST { action: "markCustomerNotified", userId: "U..." }`
   - 將該顧客名下訂單處理備註追加「已發送1對1結帳通知 (時間)」，並將狀態改為「通知結帳」。
3. 防呆冷卻：12 小時內已通知者，前端顯示黃色警示標籤「X 小時前已通知」。
