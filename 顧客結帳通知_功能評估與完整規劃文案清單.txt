一、 功能業務背景與痛點分析
================================================================================
1. 業務痛點：
   - 每次出國連線代購結束後，賣家在試算表中採購確認完畢，必須逐一私訊每一位客人核對金額。
   - 若使用 LINE 官方帳號 (LINE Official Account) 群發推播，每月免費額度僅 200 則，一旦超過將產生昂貴的推播費用。
   - 手動逐一打字或複製貼上耗時耗力，且容易算錯金額或漏掉缺貨品項，造成對帳混亂。

2. 解決方案（ShareTargetPicker 1 對 1 免額度發送）：
   - 賣家於電腦或手機打開賣家管理後台【📢 顧客結帳通知】分頁。
   - 系統自動掃描 Google 試算表，精準彙整出所有「已採購完成、待完成結帳」的真實顧客清單。
   - 賣家只需點擊「🚀 發送 1 對 1 卡片」，系統自動喚起 LINE 好友選擇器。
   - 賣家直接勾選該顧客聊天室，即可發送專屬的「Flex Message 互動結帳卡片」。
   - 此操作屬於個人發送訊息，【終生完全免費、0 額度消耗】，完全不扣官方帳號則數！
   - 顧客點擊卡片直接進入個人訂單彙整頁面（my-orders.html），一鍵完成多品項併單、選擇 7-11/全家/宅配門市，並回填匯款後五碼。

================================================================================
二、 核心運作架構與業務流程圖
================================================================================
【流程階段 1：採購標記】
  賣家在 Google 試算表【訂單明細】工作表之「採購/出貨狀態」欄位 (第 19 欄 S 欄)，
  將各商品依現場採購情況標記為「採購成功」或「缺貨斷貨」。

【流程階段 2：系統動態彙總】
  管理後台進入【📢 顧客結帳通知】分頁，向後端發出 `action=getCustomerNotifyList` 請求。
  GAS 後端自動將同一個 LINE_User_ID 的多筆訂單進行歸戶彙整：
  - 成功採購件數
  - 缺貨斷貨件數
  - 應付商品小計總額
  - 比對【顧客歸戶】帶出顧客姓名與電話

【流程階段 3：一鍵喚起 LINE 好友推播】
  賣家點擊該顧客卡片旁的「🚀 發送 1 對 1 卡片」，透過 LIFF `shareTargetPicker` 發送 Flex Message。

【流程階段 4：顧客直連結帳】
  顧客在 LINE 聊天室收到精美卡片，點擊「👉 點此開啟清單完成結帳」，
  自動帶入 UID 進入 `my-orders.html`，完成合併結帳與填寫門市。

三、 待通知顧客判定規則與資料庫篩選邏輯
================================================================================
當系統掃描【訂單明細】時，符合以下「全部條件」者才會出現在待通知名單中：

1. 篩選條件：
   - 條件 1【未完成結帳】：
     結帳編號 (第 22 欄 V 欄) 為空白，且付款狀態 (第 17 欄 Q 欄) 不為「已完成付款」或「已付款待對帳」。
   - 條件 2【有採購成功或連線登記】：
     該顧客名下至少有 1 筆訂單之採購狀態為「採購成功」、「連線登記」或「通知結帳」。
   - 條件 3【非全數缺貨】：
     若該顧客名下所有訂單皆為「缺貨斷貨」，系統將單獨標註為「⚠️ 全數缺貨（無須結帳）」，避免賣家誤發結帳催款卡片。
   - 條件 4【排除黑名單】：
     若【顧客歸戶】中該顧客被標記為黑名單，名單顯示警告標籤供賣家確認。

2. 排序權重：
   - 預設依「成功品項總額（大到小）」排序，讓賣家優先通知大單、高客單價貴賓。

六、 賣家管理後台（admin-card-generator.html）UI/UX 改造規劃
================================================================================
1. 頂部狀態列升級：
   - 增加統計儀表盤：
     * 👥 待結帳顧客總數 (如：12 位)
     * 📦 待出貨成功總件數 (如：38 件)
     * 💰 待收回總金額 (如：NT$ 48,200)
   - 增加篩選器：
     * `[ 全部待通知 ]` `[ 僅成功採購 ]` `[ 包含部分缺貨 ]` `[ 全數缺貨 ]`
   - 搜尋框：可依顧客姓名、LINE 暱稱或電話快速搜尋。

2. 顧客卡片動作按鈕：
   - 按鈕 1：`[ 🚀 LINE 1對1卡片推播 ]` ➜ 喚起 ShareTargetPicker 發送 Flex 卡片。
   - 按鈕 2：`[ 📋 複製純文字 ]` ➜ 自動將【形式 B】文字帶入剪貼簿，並彈出「已複製通知內文！」。
   - 按鈕 3：`[ 👁️ 預覽該顧客訂單 ]` ➜ 另開分頁直接查看該買家在 `my-orders.html` 的真實畫面。
   - 發送後狀態切換：
     * 點擊發送成功後，按鈕旁即時打勾標記 `✅ 已通知 (10/21 18:30)`，並同步通知後端更新試算表。

七、 後端 Google Apps Script (Code.gs) 需新增之 API 規格
================================================================================
1. API 端點：
   `GET ?action=getCustomerNotifyList`

2. 回傳 JSON 格式：
   {
     "success": true,
     "summary": {
       "totalCustomers": 12,
       "totalSuccessItems": 38,
       "totalPendingAmount": 48200
     },
     "data": [
       {
         "userId": "U111222333",
         "name": "王小美",
         "lineName": "May Wang",
         "phone": "0912345678",
         "successCount": 3,
         "outOfStockCount": 1,
         "totalAmount": 2450,
         "items": [
           { "name": "防潑水後背包", "spec": "黑色 M", "qty": 1, "status": "採購成功" },
           { "name": "保濕化妝水", "spec": "經典款 150ml", "qty": 2, "status": "採購成功" },
           { "name": "限定保溫杯", "spec": "櫻花粉", "qty": 1, "status": "缺貨斷貨" }
         ],
         "isAllOutOfStock": false,
         "notifyStatus": "未通知", // 或 "已通知 (2026/10/21 15:30)"
         "checkoutUrl": "https://liff.line.me/2011732923-rcjz7Igd?action=orders&uid=U111222333"
       }
     ]
   }

3. 標記已通知 API：
   `POST { action: "markCustomerNotified", userId: "U111222333" }`
   - 將該顧客名下待結帳訂單之處理備註追加：「已發送1對1結帳通知 (時間)」，並將狀態更新為「通知結帳」。

八、 防呆機制、防重複通知與邊界情境處理
================================================================================
1. 防重複推播冷卻機制：
   - 若 12 小時內已發送過結帳通知，卡片顯示黃色標籤「1 小時前已發送過」，防止賣家金魚腦重複騷擾顧客。
2. 顧客全數缺貨防呆：
   - 當顧客件數中 `successCount === 0` 且 `outCount > 0` 時，強制阻擋發送「結帳卡片」，改為提示發送「缺貨慰問通知」。
3. 顧客名下無有效 UID 防呆：
   - 若訂單中顧客 UID 為手動測試資料（如 GUEST 或 TEST_USER），卡片提示「⚠️ 訪客下單，無有效 LINE 帳號」，僅提供純文字複製。
